    OPERATING SYSTEM ENGINEERING · 2002–2012

    MyOS: architecture all the way down

    Experimental freestanding 32-bit x86 operating system · C++ and assembly

    A decade-long personal systems project exploring how explicit interfaces and component models can organize an operating system from boot to network services.

    Implemented the execution path from boot sector through paging, interrupts, timers, threads, SMP, device drivers, filesystems, and TCP/IP networking.

    Modeled versioned components and interfaces in XML, using XSLT to generate composition and initialization code.

    Evolved the architecture from a statically linked kernel into a resident Core plus a dynamically loaded ELF Atmosphere module, with components discovering one another through a shared runtime context rather than hidden dependencies.

    COMPILER / LANGUAGE SYSTEMS · MOJO · 2026

    xYang.mojo · YANG as a comptime type primitive

    Open source · Mojo realization of xYang · Exergy ∞ LLC

    A Mojo-native realization of my Python/JavaScript xYang project, redesigned around Mojo's comptime type system rather than implemented as a direct language port.

    The experiment explores whether YANG semantics can become part of the compile-time type system, turning a schema language into an executable semantic layer for arbitrary object models.

    • Encode YANG semantics — ranges, conditional presence, cross-field invariants, leafrefs, list keys — as parametric Mojo types
    • Resolve constraints during compilation through comptime rather than relying solely on runtime validation
    • Treat YANG as a semantic IR: Mojo types become executable representations; JSON Schema and OpenAPI become projections
    • Explore the boundary between compile-time semantic validation and runtime model behavior

    The constraint is the type

    comptime Age = YangLeaf[
    YangBuiltinUInt8,
    YangConstraints[
        Range=YangRange[18, 120]
    ]
]
    Repository · xYang.mojo

    YANG AST, XPath for must/when, runtime validator, and comptime reflection checks against modeled Mojo structs.

    github.com/exergy-connect/xYang.mojo
    Community · grant application

    Open proposal to make xYang an installable Mojo library with a reproducible demo — testing whether semantic contracts as comptime types resonate with Mojo developers.

    My systems foundations start with my Master's thesis in two thousand at Hollandse Sig-nahl-ah-pah-rah-tun — now Tahl-ess — in Hengelo, with the University of Twente. The title was Static multi-processor scheduling for heterogeneous architectures. The production compute was hex Texas Instruments TMS three-twenty C fifty-four DSP processor boards, and the team was exploring a memory-bar-connected Mercury platform as a replacement. My software mapped a directed processing graph onto those processors and generated the communication glue between them, balancing resource and communication costs against the deadline.     HPjSS++ is direct evidence of my production-grade, high-performance C++ systems programming. I built a complete SIP signaling stack from Linux sockets upward: UDP, TCP, and SCTP transports; a buffer-oriented parser; RFC 3261 transaction state machines; dialogs; authentication; and higher-level signaling services. The maintained source tree is roughly fifty-one thousand seven hundred lines across two hundred thirty-five C and C++ files, including runnable user-agent and stateful proxy applications. Its performance strategy was architectural, not cosmetic: size resources from an expected traffic profile, preallocate transaction and receive state, minimize copying with string views and lazy parsing, and make ownership and lifetime boundaries explicit. Concurrency is handled through atomic state transitions, locks, timer queues, retransmission, cancellation, and timeout machinery. This is the kind of systems work where protocol correctness, memory behavior, concurrency, and network I/O all have to hold together under sustained load.
    MyOS is the project where I explored systems architecture all the way down to the hardware. Over roughly a decade, from 2002 through 2012, I built an experimental freestanding thirty-two-bit x86 operating system in C++ and assembly. It spans the complete path from boot and memory management through interrupts, multiprocessing, threads, device drivers, filesystems, and a TCP/IP stack with services such as DHCP. The central design idea was to organize kernel facilities as versioned components and interfaces, with XML models and XSLT-generated composition making dependencies and initialization order explicit. MyOS3 evolved that architecture from one statically linked kernel into a small resident Core and an ELF-loadable Atmosphere module containing higher-level drivers, networking, and services. The Core loader relocates the module and resolves its imports against exported kernel symbols, while both partitions continue to communicate through the same interfaces and shared runtime context. This project demonstrates not only low-level implementation depth, but a long-running interest in making complex systems modular, inspectable, and evolvable.
